# Documentation vs. Codebase: What We Say We're Building vs. What Exists

**Purpose:** This is a capability-level comparison, not a line-by-line doc-accuracy check (see git history for those fixes). For each capability the documentation describes, this cross-checks the actual source code to classify it as **BUILT** (real, wired-up implementation), **PARTIAL** (real code exists but key pieces are missing, unmounted, or disconnected), or **NOT BUILT** (aspirational — no corresponding code, or only a plan document).

**Methodology:** Every row below was verified by reading the actual source referenced in the Evidence column — not by trusting another doc's claim about it.

## Overall Positioning vs. Reality

Top-level docs (`tais_frontend/README.md`, `archive/outdated/NORTH_STAR.md`) pitch TSO/TAIS as a "Digital Homesteading" platform for user-owned, privacy-first AI agents: an interview-driven no-code agent builder, backed by a blockchain-verified skill registry with cryptographic trust scoring, NFT-gated tiers, $THINK token staking economics, encrypted private/public RAG the user controls, and "RCRT" as a local context-sovereignty layer that syncs to other apps via OAuth.

If you only read the code, the actual product is narrower but mostly real: a working wallet-authenticated web platform (Express/Prisma registry + React/Vite frontend) with a genuinely functional guided-discovery agent builder, private/public RAG, OAuth-based cross-app agent portability, and a real RCRT local-sync layer (Rust binary + Electron desktop shell). As of the 2026-09-07 remediation pass (see `docs/BUG_AUDIT_2026-09.md`), skill security scanning, usage analytics, and the CTO agent assistant were all wired up for real (previously implemented code that was never mounted or reachable). A follow-up pass on 2026-09-08 then built real audit submission and trust-score computation (row 6) and wired the CLI and the standalone SDK to actually call the registry over HTTP instead of simulating success locally (rows 7, 9) — the "audit/verify never reaches the server" gap called out in the 2026-09-07 pass. A 2026-09-12 pass then built the real multi-party provenance chain row 6 was still missing (author/auditor/voucher links, real signatures, persisted and community-visible rather than a local-only cache) and wired `tais verify --provenance`/a new `tais vouch` command to it. That same pass considered, and deliberately declined, extending row 8's sandbox enforcement to the live registry server: the server has no skill-execution endpoint at all today, and `vm2` (the sandbox's underlying engine) has been EOL since 2023 with known, unpatched escape CVEs -- an acceptable-ish risk for a CLI sandboxing skills a user chose to install locally, not for a network-reachable execution surface on shared production infrastructure. Row 8 stays local/CLI-only by design, the same standing-recommendation treatment as the monetization layer below. Essentially the entire "$THINK token tier/staking/subscription" monetization layer described in the vision docs is still absent from the web platform (a disconnected, lower-fidelity on-chain balance/staking reader exists only in the separate Electron desktop app, not integrated with the registry's tier system) -- deliberately left alone, per the standing recommendation to drop that vision rather than half-build it further (see `HANDOFF.md`).

## Rollup

**19 BUILT · 2 PARTIAL · 3 NOT BUILT** (out of 24 capabilities catalogued)

The pattern: the *product* layer (agent builder, RAG, RCRT sync, cross-app portability) is real and substantially delivered. As of the 2026-09-07 remediation pass, security scanning, usage analytics, and the CTO Agent assistant have been connected to the running server as well. A 2026-09-08 follow-up then built real audit submission and trust-score computation and wired both the CLI and the standalone SDK to actually reach the registry over HTTP (rows 6, 7, 9) — previously that whole path was local-only simulation regardless of what the "community registry" language claimed. A 2026-09-12 follow-up closed the one remaining piece of row 6: a real, persisted, multi-party provenance chain (author/auditor/voucher links with real signatures, community-visible, not just a per-installation local cache), with `tais verify --provenance` and a new `tais vouch` command wired to it. That same follow-up decided row 8 stays local/CLI-only permanently rather than extending it to the live server: `vm2`'s known, unpatched sandbox-escape CVEs make it an unacceptable risk to expose as a network-reachable code-execution surface on shared production infrastructure, and the server has no skill-execution endpoint to wire it into regardless. A further 2026-09-12 pass then built row 14's App RAG half for real (an OAuth `rag:read` scope reusing existing app-registration/consent infrastructure and the already-server-held community encryption key, needing no new crypto) and designed, migrated, and tested (but did not build routes/UI for) Enterprise RAG's `Organization`/`OrganizationMember` data model — see `docs/ENTERPRISE_RAG_DATA_MODEL.md`. Row 19's Electron-only, disconnected on-chain balance/staking reader and row 14's Enterprise-RAG half are the two remaining PARTIALs. The *monetization* layer ($THINK staking, subscriptions) was designed in detail across two engineering docs and never built at all in the web platform, left alone per the standing recommendation against building that vision out further.
